# s20: Tool Refactor

前面的章节里，每新增一个工具都要手写类、构造函数、接口实现、JSON 参数解析和 input schema。工具数量变多后，这些模板代码会掩盖真正的业务逻辑。

本章重构工具系统：业务工具写成普通方法，输入使用强类型，schema 由反射自动生成，注册和动态派发交给 `ToolRegistry`。

## 运行方式

```bash
cd s20-tool-refactor
mvn exec:java -Dexec.mainClass="com.claudecode.agent.s20.Main"
```

## 本章新增能力

- 新增 `ToolRegistry`。
- 新增 `ToolContext`，显式注入工具可访问依赖。
- 用反射从 Java 输入类型生成 `input_schema`。
- 把 agent runtime state 和 tool context 分开。
- 业务工具从接口实现改成注解方法。

## 为什么要重构 Tool

旧写法中，一个简单工具也需要写很多模板代码：

```text
Tool class
  -> constructor
  -> impl ToolExecutor
  -> 手动解析 Map<String, Object>
  -> 手写 input_schema
  -> 调用业务逻辑
```

这些代码真正有价值的部分只有最后一步。

更理想的写法是：

```java
@Tool(name = "add", description = "Add two integers.")
public int add(
    @Param(name = "a", description = "First number") int a,
    @Param(name = "b", description = "Second number") int b
) {
    return a + b;
}
```

业务代码只描述输入和行为，框架负责解析、schema 和派发。

## 注解定义

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Tool {
    String name();
    String description();
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.PARAMETER)
public @interface Param {
    String name();
    String description() default "";
}
```

## ToolRegistry

`ToolRegistry` 只负责保存工具表和动态调用：

```java
public class ToolRegistry {
    private final Map<String, ToolDefinition> tools = new ConcurrentHashMap<>();
}
```

注册方式接近路由表：

```java
ToolRegistry registry = new ToolRegistry();
registry.register(new MathTools());
registry.register(new StringTools());
```

调用链路是：

```text
Agent::agentLoop()
  -> 模型返回 tool_use
  -> ToolRegistry::execute(name, params)
  -> 反射解析 input
  -> 执行业务方法
  -> 返回 tool_result
```

## 类型推断

自动推断参数类型：
- `String` -> `string`
- `int/long` -> `integer`
- `double/float` -> `number`
- `boolean` -> `boolean`
- `List` -> `array`

## 本章的局限

- 当前只有一个 `ToolContext` 类型。
- 还没有引入类似 Axum 风格的参数提取器。
- `ToolRegistry` 还没有泛型化。
- root agent、subagent、teammate 还没有各自独立的 context 类型。
- 宏只覆盖当前教程需要的 handler 形状。
