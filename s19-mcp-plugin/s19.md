# s19: MCP & Plugin System

## 目标

`s19` 的核心目标，是把前面章节里已经稳定下来的本地 tool system，扩展成一个可以接入外部 MCP server 的 agent。

这一章要讲清楚的不是"怎么做一个完整 MCP 平台"，而是更小的一件事：

**外部工具如何进入同一个 agent loop，并继续共享同一套 tool pool、permission gate 和 tool_result 回路。**

在前面的章节里，模型能调用的工具都来自 Java 代码本身，例如：

- `bash`
- `read_file`
- `write_file`
- `edit_file`

到了 `s19`，工具来源变成了两类：

- native tool：仍然由当前 Java 模块实现
- MCP tool：由外部 MCP server 进程提供

但这两类工具进入 agent 后，并不会分裂成两套执行系统。

它们共享同一条主路径：

```text
model tool_use
  -> permission check
  -> native tool 或 MCP router
  -> normalized tool_result
  -> 回到模型上下文
```

---

## 运行方式

```bash
cd s19-mcp-plugin
mvn exec:java -Dexec.mainClass="com.claudecode.agent.s19.Main"
```

## 本章新增能力

- 新增 `MCPPlugin` 接口定义插件
- 新增 `MCPPluginManager` 管理插件
- 内置 Filesystem 和 Database 插件
- 支持动态注册/注销插件

## 代码结构

```text
s19-mcp-plugin/
├── src/main/java/com/claudecode/agent/s19/
│   ├── Main.java
│   └── mcp/
│       ├── MCPPlugin.java        # 插件接口
│       ├── MCPPluginManager.java # 插件管理器
│       ├── FilesystemPlugin.java # 文件系统插件
│       └── DatabasePlugin.java   # 数据库插件
└── pom.xml
```

## MCPPlugin 接口

```java
public interface MCPPlugin {
    String name();
    String description();
    List<String> tools();
    Object callTool(String toolName, Map<String, Object> params);
    Map<String, Object> toolSpec(String toolName);
}
```

## 内置插件

### FilesystemPlugin

- `read_file`: 读取文件
- `write_file`: 写入文件
- `list_directory`: 列出目录
- `create_directory`: 创建目录
- `delete_file`: 删除文件

### DatabasePlugin

- `query`: 执行查询
- `insert`: 插入数据
- `update`: 更新数据
- `delete`: 删除数据
- `list_tables`: 列出表

## 本章的局限

- 没有实现 HTTP / SSE / Streamable HTTP transport
- 没有 OAuth 和 token refresh
- 没有 MCP resources 暴露给模型
- 没有 MCP prompts 暴露给模型
- 没有 plugin 安装、升级、签名校验
- 没有 MCP server 自动重连
