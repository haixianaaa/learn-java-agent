# s21: RAG (Retrieval-Augmented Generation)

## 目标

`s21` 的核心目标，是在 agent 系统中引入 RAG 能力：让 agent 在执行任务时，能从外部知识库中检索相关文档，将检索结果注入到 LLM 上下文中，从而让模型的回答基于事实而非幻觉。

RAG 解决的核心问题是：LLM 的知识有截止日期，且上下文窗口有限。我们不能把所有文档都塞进 prompt，但可以让 agent 按需检索。

本章要讲清楚的是 RAG 的完整流程，以及它如何嵌入到 agent loop 中。

```bash
cd s21-rag

```

## RAG 核心流程

```text
用户查询
  -> 向量嵌入 (Embedding)
  -> 向量存储检索 (VectorStore)
  -> 返回 top-K 相似文档片段
  -> 拼接到 LLM 提示词中
  -> LLM 基于检索上下文生成回答
```

拆开来看，一共有五个步骤：

1. **文档加载 (Document Loading)**：从文件、字符串等来源加载原始文档
2. **文本分块 (Chunking)**：将长文档切分为适合嵌入模型处理的小片段
3. **向量嵌入 (Embedding)**：将文本转换为高维数值向量
4. **相似度检索 (Retrieval)**：用查询向量在向量存储中找到最相似的文档片段
5. **上下文注入 (Context Injection)**：将检索结果拼接到 LLM 的提示词中

## 各组件说明

### Document / DocumentChunk

`Document` 是原始文档的载体，包含 id、内容和元数据。`DocumentChunk` 是分块后的片段，额外记录了在原文中的起止位置。

### DocumentLoader

负责从不同来源加载文档：

- `loadFromString`：从字符串加载
- `loadFromFile`：从文件加载
- `loadFromDirectory`：从目录批量加载

### Chunker

将长文档切分为小片段。策略是：

1. 按 `chunkSize` 切分
2. 在切分点附近寻找自然断点（句号、换行、空格）
3. 相邻块之间保留 `overlapSize` 的重叠区域

重叠区域的作用是避免语义在切分边界处断裂——同一个句子可能被拆到两个块里，重叠确保它至少在一个块中是完整的。

### Embedding

将文本转换为浮点向量。本章使用**模拟嵌入**：基于文本哈希生成确定性向量，相同文本始终产生相同向量。

> ⚠️ 模拟嵌入仅用于演示 RAG 流程。生产环境应使用真实的嵌入模型（如 OpenAI text-embedding-ada-002、BGE、E5 等）。

相似度计算使用**余弦相似度**：

```text
cosine(A, B) = (A · B) / (||A|| × ||B||)
```

值域 [-1, 1]，越接近 1 表示越相似。

### VectorStore

存储文档片段的向量表示，支持：

- `addChunk`：添加单个片段
- `addChunks`：批量添加
- `search`：返回 top-K 最相似结果
- `searchWithThreshold`：带最低相似度阈值过滤

### RAGRetriever

封装检索逻辑：

- `retrieve`：返回带分数的检索结果
- `retrieveContext`：返回格式化的上下文文本，可直接拼入 prompt

### RAGPipeline

串联完整流程的入口：

```java
RAGPipeline pipeline = new RAGPipeline();
pipeline.indexDocument("文档内容...", Map.of("source", "doc.txt"));
String context = pipeline.query("用户问题");
String fullPrompt = pipeline.buildPrompt("系统提示词", "用户问题");
```

## RAG 在 Agent Loop 中的位置

在完整的 agent 架构中，RAG 通常以 **RAG Tool** 的形式存在：

```text
Agent Loop:
  1. 用户输入
  2. 模型推理 -> 返回 tool_use (name="rag_search", query="...")
  3. Agent 执行 RAG Tool
     -> RAGRetriever.retrieve(query)
     -> 返回检索结果作为 tool_result
  4. 模型基于检索结果继续推理
  5. 返回最终回答
```

这样做的好处：

- **按需检索**：只在模型认为需要时才检索，不浪费上下文窗口
- **动态知识**：知识库可以随时更新，无需重新训练模型
- **可追溯**：检索结果带有来源信息，回答有据可查

## 本章的局限

- 嵌入是模拟的，不是真实语义嵌入
- 向量存储是内存中的，没有持久化
- 没有实现混合检索（向量 + 关键词）
- 没有实现重排序（Reranking）
- 没有实现查询改写（Query Rewriting）
- 没有将 RAG 封装为 Agent Tool（需要结合前面章节的 tool 系统）
- 分块策略只有固定长度 + 重叠，没有语义分块
